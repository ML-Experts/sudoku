# UC-16 — Frontend

## Cel
- Udostępnić użytkownikowi read-only przeglądarkę przygotowanego datasetu.
- Pokazać w `UI` artefakty preview zapisane wcześniej podczas `UC-12`.
- Pozwolić ocenić jakość preprocessingu bez dodatkowego kroku zatwierdzania.

## Zakres widoku
### Lista datasetów
- `FE` pokazuje listę już przygotowanych datasetów i pozwala wejść do szczegółów wybranego rekordu.
- Lista może wykorzystywać istniejące `GET /api/datasets/processed` jako punkt wejścia.

### Szczegóły datasetu
- `FE` pokazuje metadane datasetu:
  - `name`,
  - `fileName`,
  - `preprocessingProfile`,
  - `createdAtUtc`,
  - `sampleCounts`,
  - `sourceReports`,
  - `warnings`.
- `FE` pokazuje także sekcję preview per źródło.

### Preview dla `board`
- lista plansz należących do danego źródła,
- po wyborze planszy:
  - obraz planszy po korekcji perspektywy tuż przed cięciem,
  - lista lub siatka elementów gotowych do wejścia do datasetu.

### Preview dla `digit`
- lista albo paginowana galeria finalnych próbek po preprocessingu,
- jeśli dostępna jest etykieta, `FE` pokazuje ją jako metadane pomocnicze.

## Kontrakty `FE -> BE`
### Minimalny zestaw endpointów
- `GET /api/datasets/processed`
- `GET /api/datasets/processed/{name}`
- `GET /api/datasets/processed/{name}/preview`
- `GET /api/datasets/processed/{name}/preview/images/{imageId}`

Dokładny kształt URL-i może ulec doprecyzowaniu implementacyjnemu, ale `FE` nie powinno znać fizycznych ścieżek systemowych.

## Oczekiwane modele odpowiedzi
### `ProcessedDatasetDetailsApiResponse`
- pełne metadane datasetu,
- rozszerzenie istniejącego kontraktu listy o dane potrzebne przeglądarce.

### `ProcessedDatasetPreviewApiResponse`
- rekord datasetu lub źródła,
- sekcja `boardSources`,
- sekcja `digitSources`,
- referencje do obrazów preview możliwe do pobrania osobnym endpointem.

### `ProcessedBoardPreviewItemApiResponse`
- `sourceName`,
- `boardName`,
- `split`,
- `correctedBoardImageId`,
- lista `cellPreviewItems`.

### `ProcessedBoardCellPreviewItemApiResponse`
- `cellIndex`,
- `label`,
- `imageId`.

### `ProcessedDigitPreviewItemApiResponse`
- `sampleIndex`,
- `label`,
- `split`,
- `imageId`.

### `ImageApiResponse`
- `mimeType`,
- `base64`.

`FE` może korzystać z już używanego w projekcie wzorca renderowania obrazów `base64`.

## Zasady działania
- Widok `UC-16` jest częścią strefy administracyjnej i wymaga tokenu z `UC-13`.
- `FE` nie uruchamia ponownie przygotowania datasetu tylko po to, aby pokazać preview.
- `FE` nie próbuje lokalnie rekonstruować danych z `.npz`; pokazuje tylko to, co `BE` udostępni przez API.
- `FE` nie pokazuje jeszcze akcji `delete`, `exclude`, `reject`, `rebuild`.
- Jeśli dataset nie ma zapisanych artefaktów preview, UI powinno pokazać czytelną informację diagnostyczną zamiast pustego stanu sugerującego błąd użytkownika.

## Błędy API
- `401 Unauthorized` dla braku lub wygaśnięcia tokenu.
- `404 Not Found` jeśli dataset albo żądany artefakt preview nie istnieje.
- `409 Conflict` nie jest typowym błędem `UC-16`, ponieważ widok ma charakter read-only.
- `500 Internal Server Error` gdy `BE` nie potrafi odczytać zapisanych metadanych lub artefaktów preview.

## Relacja do `UC-17`
- `UC-16` służy wyłącznie do oglądania.
- Wszelkie akcje selekcji pojedynczych `boardów`, komórek albo `digitów` należą do `UC-17`.

## Kryteria akceptacji
- Użytkownik może wejść do przeglądarki przygotowanego datasetu bez ponownego uruchamiania `UC-12`.
- Dla `board` użytkownik widzi planszę po korekcji perspektywy i gotowe elementy po preprocessingu.
- Dla `digit` użytkownik widzi finalne próbki po preprocessingu.
- Widok nie wprowadza jeszcze żadnych operacji modyfikujących dataset.
