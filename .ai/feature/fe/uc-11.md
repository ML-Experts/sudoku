# UC-11 — Frontend

## Cel
- Pobrać z `BE` listę możliwych datasetów dostępnych do dalszego przygotowania.
- Pokazać administratorowi kandydatów datasetowych z rozróżnieniem typu `board` i `digit`.
- Przygotować widok pod kolejny krok workflow, bez uruchamiania jeszcze przygotowania danych.

## Adres / endpoint chroniony `FE -> BE`
- `GET /api/datasets/raw-candidates`

## Kontrakty
### Lista surowych kandydatów datasetowych
- `GET /api/datasets/raw-candidates`
- `200 OK` -> `RawDatasetCandidateApiResponse[]`

```json
[
  {
    "name": "Plansze",
    "type": "board"
  },
  {
    "name": "t10k",
    "type": "digit"
  }
]
```

## Błędy API
- `401 Unauthorized` dla braku lub wygaśnięcia tokenu administracyjnego.
- `500 Internal Server Error` dla nieoczekiwanego błędu po stronie `BE`.

```json
{
  "errorType": "admin_token_expired",
  "message": "Sesja administracyjna wygasła. Zaloguj się ponownie."
}
```

## Modele API wejściowe
- Brak modelu JSON wejściowego.

## Modele API wyjściowe
- `RawDatasetCandidateApiResponse`
  - `name: string`
  - `type: string` (`board` | `digit`)
- `ErrorApiResponse`
  - `errorType: string`
  - `message: string`

## Zasady działania
- `UC-11` po stronie `FE` obejmuje wyłącznie pobranie i prezentację listy kandydatów datasetowych.
- Widok `UC-11` jest częścią strefy administracyjnej i wymaga tokenu z `UC-13`.
- `FE` nie realizuje uploadu datasetów przez HTTP i nie komunikuje się bezpośrednio z `ML`.
- `FE` nie rozpoznaje samodzielnie typu datasetu; pole `type` pochodzi z `BE`, który nadaje je na podstawie folderu źródłowego `boards` albo `digits`.
- `FE` nie uruchamia jeszcze przygotowania `{name}.npz`; ten etap należy do kolejnego use case'u.
- Jeśli lista jest pusta, UI pokazuje stan typu "brak wykrytych datasetów".
- Po `401 Unauthorized` `FE` czyści sesję administracyjną i wraca do logowania zgodnie z `UC-13`.
