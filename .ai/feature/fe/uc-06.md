# UC-06 — Frontend

## Cel
- Pokazać użytkownikowi administracyjnemu listę modeli bazowych z rejestru oraz listę gotowych datasetów `.npz`.
- Umożliwić wybór dokładnie jednego modelu bazowego i dokładnie jednego datasetu przetworzonego.
- Wysłać chronione żądanie startu treningu i od razu otrzymać `runName`, które zastępuje wcześniejsze, niepotrzebne pojęcie `training_id`.
- Po akceptacji żądania przejść do monitorowania runu przez kanał `WebSocket` po stronie `BE`, bez bezpośredniej komunikacji z `ML`.
- Zablokować możliwość tworzenia kolejki nowych runów: drugi klik Start nie może uruchomić drugiego treningu, ale aktywny run można anulować.

## Adresy / endpointy chronione `FE -> BE`
- `GET /api/models/registry`
- `GET /api/datasets/processed`
- `POST /api/trainings`
- `POST /api/trainings/{runName}/cancel`
- `WebSocket /ws/trainings/{runName}`

### Kanał postępu
- `WebSocket /ws/trainings/{runName}`
- kanał jest logicznie powiązany z jednym `runName`,
- używa tego samego tokenu administracyjnego z `UC-13`,
- klient dostarcza token przez `accessTokenFactory`, a nie przez query string,
- `FE` nie łączy się bezpośrednio z `ML`; postęp przychodzi wyłącznie z `BE`,
- po połączeniu `BE` najpierw wysyła `snapshot`, a następnie kolejne eventy stanu.

## Semantyka właściwości i reguły tworzenia
- `RegistryModelListItemApiResponse.name`:
  - jest logiczną nazwą wpisu rejestru modeli,
  - odpowiada katalogowi `models/registry/{name}`,
  - `FE` używa jej jako wartości selecta lub radio buttona,
  - użytkownik nie wpisuje jej ręcznie.
- `RegistryModelListItemApiResponse.sourceType`:
  - `bootstrap` oznacza model seed / imported bez własnego `runName`,
  - `trainingRun` oznacza model pochodzący z wcześniejszego treningu,
  - `FE` może pokazać tę informację jako badge lub metadane pomocnicze.
- `RegistryModelListItemApiResponse.sourceRunName`:
  - może być `null` dla modeli bootstrap,
  - jeśli istnieje, pozwala później połączyć model z ekranem szczegółów treningu.
- `RegistryModelListItemApiResponse.parentModelName`:
  - może być `null` dla modeli bootstrap albo treningu od zera,
  - może wskazywać model bazowy użyty do fine-tuningu lub transfer learningu.
- `RegistryModelListItemApiResponse.canStartTraining`:
  - decyduje, czy dany wpis można wskazać w formularzu startu treningu,
  - `FE` nie powinno próbować odgadywać tego samodzielnie na podstawie `sourceType` ani `trainingMode`.
- `CreateTrainingRunApiEntry.baseModelName`:
  - pochodzi bezpośrednio z odpowiedzi `GET /api/models/registry`,
  - odnosi się do wpisu rejestru modelu, a nie do konkretnego pliku artefaktu,
  - `FE` nie wysyła żadnej ścieżki pliku modelu, katalogu ani manifestu.
- `CreateTrainingRunApiEntry.processedDatasetName`:
  - pochodzi bezpośrednio z odpowiedzi `GET /api/datasets/processed`,
  - `FE` nie wysyła rozszerzenia `.npz` ani ścieżki systemowej.
- `TrainingRunApiResponse.runName`:
  - jest identyfikatorem runu w API i jednocześnie nazwą plikowego rekordu po stronie serwera,
  - zastępuje wcześniejsze pojęcie `training_id`,
  - `FE` otrzymuje je od razu po zaakceptowaniu startu runu, a nie dopiero po zakończeniu treningu.
- `TrainingRunApiResponse.producedModelName`:
  - jest logiczną nazwą docelowego wpisu modelu, który ma powstać po zakończeniu runu,
  - w MVP może być równe `runName`, ale `FE` powinno traktować te pola jako semantycznie różne.
- `TrainingRunApiResponse.status`:
  - po starcie powinno być co najmniej `queued`,
  - dalsze statusy obejmują `starting`, `running`, `cancelling`, `succeeded`, `failed`, `cancelled`.
- `TrainingRunApiResponse.trainingMode`, `trainingProfileName`, `augmentationProfileName`, `benchmarkName`, `seed`:
  - są metadanymi resolved przez `BE`,
  - w MVP użytkownik nie wpisuje ich ręcznie,
  - `FE` może je pokazać jako sekcję "parametry startu".
- `TrainingRunApiResponse.progressChannelUrl`:
  - jest adresem względnym po stronie publicznego `BE`,
  - `FE` wykorzystuje go do połączenia klienta `WebSocket` / `SignalR`,
  - token do połączenia jest przekazywany przez `accessTokenFactory`.
- `TrainingRunSocketEventApiResponse.sequence`:
  - jest rosnącym numerem zdarzenia,
  - `FE` może ignorować opóźnione eventy o niższym numerze niż ostatnio wyrenderowany stan.
- `TrainingRunSocketEventApiResponse.result.reportStatus`:
  - opisuje stan raportu końcowego niezależnie od używalności modelu,
  - `corrupted` albo `missing` nie musi oznaczać, że model jest bezużyteczny.

## Błędy API
- `400 Bad Request` dla pustego wyboru modelu albo datasetu.
- `401 Unauthorized` dla braku lub wygaśnięcia tokenu administracyjnego.
- `404 Not Found` jeśli model albo dataset zniknęły między odczytem listy a kliknięciem Start.
- `409 Conflict` jeśli inny run jest już aktywny albo jeśli serwer nie może utworzyć nowego runu z powodu konfliktu nazwy plikowej.
- `422 Unprocessable Content` jeśli wybrany wpis rejestru nie jest poprawnym modelem bazowym do treningu albo ma niepoprawny manifest.
- `503 Service Unavailable` jeśli usługa treningowa jest chwilowo niedostępna.
- `504 Gateway Timeout` jeśli start treningu nie został potwierdzony w oczekiwanym czasie.

```json
{
  "errorType": "training_run_already_active",
  "message": "Inny run treningowy jest już aktywny. System nie tworzy kolejki kolejnych runów."
}
```

```json
{
  "errorType": "registry_model_entry_not_found",
  "message": "Model cnn-mnist-baseline nie istnieje w rejestrze modeli."
}
```

```json
{
  "errorType": "processed_dataset_not_found",
  "message": "Dataset sudokuDigitsV1.npz nie istnieje w katalogu danych przetworzonych."
}
```

```json
{
  "errorType": "training_run_cancel_not_allowed",
  "message": "Run nie jest już aktywny i nie może zostać anulowany."
}
```

## Zasady działania
- Widok `UC-06` jest częścią strefy administracyjnej i wymaga tokenu z `UC-13`.
- `FE` nie buduje samodzielnie listy modeli ani datasetów; zawsze pobiera je z `BE`.
- W formularzu użytkownik wybiera dokładnie jeden wpis modelu bazowego z rejestru i dokładnie jeden dataset `.npz`.
- `FE` nie zna fizycznego layoutu `model.json` ani `artifacts/`; widzi jedynie logiczne pola zwrócone przez API.
- Model bootstrap bez własnego `runName` może być normalnie pokazany na liście i wybrany do treningu, jeśli `canStartTraining = true`.
- `FE` nie powinno eksponować pojęcia `training_id`; jedynym identyfikatorem runu jest `runName`.
- Po sukcesie `POST /api/trainings` interfejs powinien zachować `runName`, `producedModelName` i `progressChannelUrl`, aby od razu przejść do monitoringu runu.
- `FE` łączy się z kanałem `WebSocket` po stronie `BE`, nie po stronie `ML`.
- `FE` inicjalizuje połączenie kanału postępu z użyciem `accessTokenFactory` i tego samego `JWT`, który wykorzystuje dla chronionych requestów HTTP.
- Po połączeniu `FE` najpierw renderuje `snapshot`, a potem reaguje na kolejne eventy `progress`, `completed`, `failed` i `cancelled`.
- Utrata połączenia `WebSocket` nie zatrzymuje runu; `FE` powinno próbować reconnectu i po powrocie odtworzyć stan na podstawie `snapshot` albo `GET /api/trainings/{runName}` z późniejszego use case'u.
- Przycisk Start powinien zostać zablokowany po wysłaniu pierwszego żądania i pozostać nieaktywny, gdy system ma aktywny run.
- Jeśli `POST /api/trainings` zwróci `409 training_run_already_active`, `FE` nie próbuje startować drugiego runu; zamiast tego powinno przejść do monitoringu już aktywnego runu.
- `FE` powinno udostępnić akcję anulowania aktywnego runu przez `POST /api/trainings/{runName}/cancel`.
- Po `401 Unauthorized` `FE` czyści sesję administracyjną i wraca do logowania.
- Po `503` albo `504` formularz powinien zachować wybrane wartości, aby użytkownik mógł spróbować ponownie bez ponownego wybierania modelu i datasetu.
- Jeśli `result.reportStatus` ma wartość `corrupted` albo `missing`, UI powinno pokazać ostrzeżenie o uszkodzonym raporcie, ale nie blokować informacji, że model może być nadal używalny.
- Payloady JSON używają kluczy w `camelCase`.

## Zasady działania
- Widok `UC-06` jest częścią strefy administracyjnej i wymaga tokenu z `UC-13`.
- `FE` nie buduje samodzielnie listy modeli ani datasetów; zawsze pobiera ją z `BE`.
- W formularzu użytkownik wybiera dokładnie jeden wpis modelu bazowego z rejestru i dokładnie jeden dataset `.npz`.
- `FE` nie zna fizycznego layoutu `model.json` ani `artifacts/`; widzi jedynie logiczne pola zwrócone przez API.
- Model bootstrap bez własnego `runName` może być normalnie pokazany na liście i wybrany do treningu, jeśli `canStartTraining = true`.
- `FE` nie powinno eksponować pojęcia `training_id`; jedynym identyfikatorem runu jest `runName`.
- Po sukcesie `POST /api/trainings` interfejs powinien zachować `runName`, `producedModelName` i `progressChannelUrl`, aby od razu przejść do obsługi `UC-07`.
- UI może pokazać resolved metadane startu, takie jak `trainingMode`, `trainingProfileName`, `augmentationProfileName`, `benchmarkName` i `seed`.
- Po `401 Unauthorized` `FE` czyści sesję administracyjną i wraca do logowania.
- Po `503` albo `504` formularz powinien zachować wybrane wartości, aby użytkownik mógł spróbować ponownie bez ponownego wybierania modelu i datasetu.
- Payloady JSON używają kluczy w `camelCase`.
