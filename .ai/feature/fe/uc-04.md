# UC-04 — Frontend

## Cel
- Pokazać wybrany obraz przykładowy.
- Przeprowadzić dwa etapy preprocessingu i zaprezentować ich wyniki użytkownikowi.

## Endpointy `FE -> BE`
- `GET /api/examples/{name}`
- `PUT /api/examples/{name}/preprocess/board`
- `PUT /api/examples/preprocess/cells`

## Kontrakty
### Podgląd przykładu
- `GET /api/examples/{name}` -> `ImageApiResponse`

```json
{
  "mimeType": "image/jpeg",
  "base64": "/9j/4AAQSkZJRgABAQAAAQABAAD..."
}
```

### Etap 1 preprocessingu
- `PUT /api/examples/{name}/preprocess/board` -> `ImageApiResponse`

```json
{
  "mimeType": "image/png",
  "base64": "iVBORw0KGgoAAAANSUhEUgAA..."
}
```

### Etap 2 preprocessingu
- `PUT /api/examples/preprocess/cells`
- Request body: `ImageApiEntry`
- Response: `CellsGridApiResponse`

```json
{
  "cells": [
    [
      {
        "mimeType": "image/png",
        "base64": "iVBORw0KGgoAAAANSUhEUgAA..."
      }
    ]
  ]
}
```

## Modele API wejściowe
- `ImageApiEntry`
  - `mimeType: string`
  - `base64: string`

## Modele API wyjściowe
- `ImageApiResponse`
  - `mimeType: string`
  - `base64: string`
- `CellsGridApiResponse`
  - `cells: ImageApiResponse[9][9]`
- `ErrorApiResponse`
  - `errorType: string`
  - `message: string`

## Zasady działania
- FE przechowuje wynik etapu 1 preprocessingu w pamięci klienta i wysyła go do etapu 2.
- FE nie zakłada, że wynik etapu 1 jest zapisany po stronie `BE` lub `ML`.
- Podgląd obrazu i wynik etapu 1 używają tego samego modelu `ImageApiResponse`.
- Wynik etapu 2 jest prezentowany jako siatka `9x9` obrazów komórek.
- Komunikaty błędów pochodzą z `ErrorApiResponse` z polami `errorType` i `message`.
