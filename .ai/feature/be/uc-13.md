# UC-13 — Backend

## Cel
- Udostępnić prosty endpoint logowania administracyjnego z jednym współdzielonym hasłem.
- Generować krótko żyjący `JWT` z datą wygaśnięcia wyliczaną z konfiguracji aplikacji.
- Rozdzielić publiczny tryb demo bez logowania od trybu administracyjnego wymagającego tokenu.
- Chronić operacje administracyjne przez nagłówek `Authorization: Bearer`.

## Endpoint publiczny logowania `FE -> BE`
- `POST /api/auth/login`

## Endpointy publiczne bez tokenu (tryb demo)
- `GET /api/examples`
- `GET /api/examples/{name}`
- `GET /api/examples/{name}/download`
- `PUT /api/examples/{name}/preprocess/board`
- `PUT /api/examples/preprocess/cells`
- `POST /api/examples/{name}/solve` lub równoważny endpoint solve dla wybranego przykładu z `UC-05`

## Endpointy administracyjne chronione tokenem
- `POST /api/examples`
- `GET /api/datasets/raw-candidates`
- `POST /api/datasets/processed`
- `GET /api/datasets/processed`
- `GET /api/models/registry`
- `POST /api/trainings`
- `GET /api/trainings`
- `GET /api/trainings/{runName}`
- `GET /api/models`
- `PUT /api/models/active`
- `WebSocket /ws/trainings/{runName}`

## Kontrakty
### `POST /api/auth/login`
- Request body: `AdminLoginApiEntry`
- `200 OK` -> `AuthTokenApiResponse`

```json
{
  "password": "********"
}
```

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "tokenType": "Bearer",
  "expiresAtUtc": "2026-04-11T12:30:00Z"
}
```

### Nagłówek dla endpointów chronionych

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

## Błędy API
- `401 Unauthorized` dla błędnego hasła, braku tokenu, tokenu niepoprawnego lub wygasłego.

```json
{
  "errorType": "invalid_credentials",
  "message": "Niepoprawne hasło administracyjne."
}
```

```json
{
  "errorType": "admin_token_expired",
  "message": "Sesja administracyjna wygasła. Zaloguj się ponownie."
}
```

## Modele API wejściowe
- `AdminLoginApiEntry`
  - `password: string`

## Modele API wyjściowe
- `AuthTokenApiResponse`
  - `accessToken: string`
  - `tokenType: string`
  - `expiresAtUtc: string` (`ISO-8601 UTC`)
- `ErrorApiResponse`
  - `errorType: string`
  - `message: string`

## DTO / wyniki use case'ów
- `LoginCommandResultDto`
  - `accessToken`
  - `tokenType`
  - `expiresAtUtc`

## Zasady działania
- Login przyjmuje wyłącznie pole `password`; nie wprowadzamy `username`, `email`, kont użytkowników, ról ani refresh tokenów.
- Backend porównuje hasło z jedną współdzieloną wartością konfiguracyjną. Na produkcji wartość hasła jest wstrzykiwana przez workflow z `GitHub Secret` do `appsettings.production.json` albo równoważnego override'u środowiskowego.
- Czas życia tokenu pochodzi z `appsettings*.json`; odpowiedź loginu zwraca także `expiresAtUtc`, aby `FE` nie musiał zgadywać momentu wygaśnięcia.
- `JWT` jest podpisywany i walidowany po stronie `BE`, a jego użycie ogranicza się do prostej bramki administracyjnej projektu.
- Brak logowania nie blokuje scenariusza demo na istniejących przykładach: użytkownik może wybrać przykład, wykonać preprocessing, rozpoznać planszę i uzyskać wynik rozwiązania z overlayem.
- `POST /api/examples` jest traktowany jako operacja administracyjna, ponieważ zapisuje nowy plik do serwerowego magazynu `examples`.
- Odczyt i obsługa ekranów datasetów, treningów i modeli należą do strefy administracyjnej nawet wtedy, gdy część z tych endpointów używa metod `GET`.
- Brakujący, niepoprawny lub wygasły token zwraca `401 Unauthorized`; `403 Forbidden` nie jest tu potrzebne, bo nie modelujemy ról.
- Ochrona endpointów administracyjnych powinna być realizowana przez współdzielony mechanizm `ASP.NET` (`[Authorize]`, policy albo middleware), a nie duplikowana w kontrolerach.
