# UC-16 — Backend

## Cel
- Udostępnić publiczne, chronione API do przeglądania wcześniej przygotowanych datasetów i ich artefaktów preview.
- Pozostać `source of truth` dla rekordów datasetowych, metadanych i referencji do zapisanych obrazów preview.
- Nie wprowadzać dodatkowego stanu zatwierdzania pomiędzy przygotowaniem datasetu a jego oglądaniem.

## Zakres odpowiedzialności
- `BE` przyjmuje, że `UC-12` już zapisał:
  - finalny `.npz`,
  - rekord metadanych,
  - artefakty preview.
- `BE` odpowiada za:
  - odczyt listy i detalu przygotowanych datasetów,
  - odczyt indeksu preview,
  - serwowanie pojedynczych obrazów preview do `FE`.

## Adresy / endpointy chronione `FE -> BE`
- `GET /api/datasets/processed`
- `GET /api/datasets/processed/{name}`
- `GET /api/datasets/processed/{name}/preview`
- `GET /api/datasets/processed/{name}/preview/images/{imageId}`

Dokładny dobór końcówek może zostać doprecyzowany implementacyjnie, ale `BE` powinien ukrywać fizyczne ścieżki plików.

## Kontrakty publiczne
### `GET /api/datasets/processed/{name}`
- `200 OK` -> `ProcessedDatasetDetailsApiResponse`
- `404 Not Found` -> `ErrorApiResponse`

Odpowiedź zawiera co najmniej:
- `name`,
- `fileName`,
- `preprocessingProfile`,
- `createdAtUtc`,
- `sources`,
- `sampleCounts`,
- `sourceReports`,
- `warnings`.

### `GET /api/datasets/processed/{name}/preview`
- `200 OK` -> `ProcessedDatasetPreviewApiResponse`
- `404 Not Found` -> `ErrorApiResponse`

Odpowiedź zawiera co najmniej:
- informacje o źródłach `board` i `digit`,
- listę plansz dostępnych do podglądu,
- referencje do obrazów preview,
- minimalne metadane potrzebne `FE` do renderowania list i siatek.

### `GET /api/datasets/processed/{name}/preview/images/{imageId}`
- `200 OK` -> `ImageApiResponse`
- `404 Not Found` -> `ErrorApiResponse`

`BE` zwraca obrazy w tym samym modelu `ImageApiResponse`, który jest już używany w innych częściach systemu.

## Rekordy i metadane
### Rozszerzenie rekordu datasetu
Rekord przygotowanego datasetu po stronie `BE` powinien zostać rozszerzony o dane potrzebne do `UC-16`, np.:
- identyfikator albo katalog root preview,
- indeks preview per źródło,
- referencje do plansz i próbek,
- ewentualne ostrzeżenia diagnostyczne dotyczące brakujących artefaktów preview.

### Zasada utrwalenia
- `BE` zapisuje metadane preview w tym samym workflow, w którym finalizuje wynik `UC-12`.
- `BE` nie traktuje preview jako informacji chwilowej tylko jako część rekordu przygotowanego datasetu.

## Zasady działania
- Wszystkie endpointy `UC-16` są chronione tokenem z `UC-13`.
- `BE` nie uruchamia ponownie `ML` tylko po to, by wygenerować preview na żądanie użytkownika.
- `BE` odczytuje zapisane już artefakty preview i wystawia je przez publiczne API.
- `BE` nie dopuszcza jeszcze żadnych operacji modyfikujących dataset.
- `BE` nie usuwa automatycznie plików preview ani plików źródłowych.

## Zależność od `UC-12`
- `UC-12` pozostaje odpowiedzialny za przygotowanie datasetu.
- `UC-16` zakłada, że `UC-12` zapisuje nie tylko `.npz`, ale też preview.
- Jeśli preview dla danego datasetu nie istnieje, `BE` powinien zwrócić czytelny błąd domenowy albo status częściowej dostępności danych, a nie próbować cicho odtwarzać brakujące artefakty.

## Błędy API
- `401 Unauthorized` dla braku lub wygaśnięcia tokenu.
- `404 Not Found` jeśli dataset albo żądany artefakt preview nie istnieje.
- `500 Internal Server Error` jeśli rekord metadanych albo zapisane preview są uszkodzone lub nieczytelne.

Przykład:

```json
{
  "errorType": "processed_dataset_preview_not_found",
  "message": "Dataset sudokuDigitsV1 nie posiada zapisanych artefaktów preview."
}
```

## Modele API wyjściowe
- `ProcessedDatasetDetailsApiResponse`
- `ProcessedDatasetPreviewApiResponse`
- `ProcessedBoardPreviewItemApiResponse`
- `ProcessedBoardCellPreviewItemApiResponse`
- `ProcessedDigitPreviewItemApiResponse`
- `ImageApiResponse`
- `ErrorApiResponse`

## Założenia implementacyjne
- Publiczne endpointy dopinamy do istniejącego `DatasetsController`.
- Logika odczytu szczegółów i preview trafia do warstwy `Application`, a nie bezpośrednio do kontrolera.
- `Infrastructure` odpowiada za odczyt metadanych preview i obrazów z systemu plików.
- `BE` nie eksponuje bezpośrednio ścieżek systemowych w kontraktach HTTP.

## Relacja do `UC-17`
- `UC-16` nie dodaje endpointów `delete`, `exclude`, `reject`, `rebuild`.
- Wszelkie operacje selekcji próbek i budowania nowej wersji datasetu są poza zakresem tej historyjki.

## Kryteria akceptacji
- `BE` udostępnia chronione endpointy do odczytu zapisanych datasetów i ich preview.
- Odpowiedzi pozwalają `FE` zrenderować osobno preview dla `board` i `digit`.
- Workflow nie wymaga osobnego kroku zatwierdzania po `UC-12`.
- `UC-16` pozostaje w całości read-only.
