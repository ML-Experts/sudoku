# UC-13 — Machine Learning

## Udział warstwy
- `UC-13` nie wprowadza publicznego logowania ani walidacji tokenu po stronie `ML`.
- Serwis `ML` pozostaje usługą wewnętrzną wywoływaną przez `BE`.

## Endpointy wewnętrzne `BE -> ML`
- Brak nowych endpointów w ramach `UC-13`.

## Kontrakty
- Brak nowych kontraktów `BE -> ML` w ramach `UC-13`.
- Istniejące endpointy `ML` nie przyjmują pola `password` ani nagłówka `Authorization` z tokenem użytkownika końcowego.

## Modele API / DTO
- Brak nowych modeli `ApiEntry`, `ApiResponse` i `Dto`.

## Zasady działania
- `FE` nie komunikuje się bezpośrednio z `ML`; cała autoryzacja administracyjna jest egzekwowana w publicznym `API` Backendu.
- `ML` nie generuje, nie odświeża i nie waliduje `JWT` użytkownika.
- Brak poprawnego tokenu powinien zatrzymać żądanie po stronie `BE` zanim dojdzie do wywołania `ML`.
- Jeśli w przyszłości pojawi się potrzeba zabezpieczenia komunikacji `BE -> ML`, będzie to osobny mechanizm infrastrukturalny poza zakresem `UC-13`.
