# UC-04 — Machine Learning

## Cel
- Wykonać dwa etapy preprocessingu na żądanie `BE` bez utrwalania wyników:
  - wykrycie planszy i korekcja perspektywy,
  - podział obrazu planszy na siatkę `9x9`.

## Endpointy wewnętrzne `BE -> ML`
- `PUT /ml/preprocess/board`
- `PUT /ml/preprocess/cells`

## Kontrakty
### `PUT /ml/preprocess/board`
- Request: `ImageApiEntry`
- Response: `ImageApiResponse`

```json
{
  "mimeType": "image/jpeg",
  "base64": "/9j/4AAQSkZJRgABAQAAAQABAAD..."
}
```

```json
{
  "mimeType": "image/png",
  "base64": "iVBORw0KGgoAAAANSUhEUgAA..."
}
```

### `PUT /ml/preprocess/cells`
- Request: `ImageApiEntry`
- Response: `CellsGridApiResponse`

```json
{
  "cells": [
    [
      {
        "mimeType": "image/png",
        "base64": "iVBORw0KGgoAAAANSUhEUgAA..."
      }
    ]
  ]
}
```

## Błędy API
- `422 Unprocessable Content`

```json
{
  "errorType": "cells_extraction_failed",
  "message": "Nie udało się poprawnie podzielić planszy na siatkę 9x9."
}
```

## Modele API wejściowe
- `ImageApiEntry`
  - `mimeType: string`
  - `base64: string`

## Modele API wyjściowe
- `ImageApiResponse`
  - `mimeType: string`
  - `base64: string`
- `CellsGridApiResponse`
  - `cells: ImageApiResponse[9][9]`
- `ErrorApiResponse`
  - `errorType: string`
  - `message: string`

## DTO / wyniki use case'ów
- `PreprocessBoardCommandResultDto`
  - `mimeType`
  - `base64`
- `ExtractCellsCommandResultDto`
  - `cells`

## Zasady działania
- `ML` nie zapisuje wyników preprocessingu na dysku.
- `ML` zwraca wynik bezpośrednio do `BE`, a `BE` odsyła go do `FE`.
- Oba endpointy przyjmują i zwracają JSON z kluczami w `camelCase`.
- Etap `cells` zakłada, że wejściem jest obraz planszy po korekcji perspektywy, przekazany jako `ImageApiEntry`.
